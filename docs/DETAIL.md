# 飞书确认桥接

把 DSH 需要人工确认的请求同步到飞书，让不在电脑边时也能作答；电脑端与飞书**先提交者生效**。

## 覆盖的交互

- `ask_user_question`：单选 / 多选 / 自由文本；一次请求里的多个问题会渲染到同一张卡片，可一次提交。
- 权限审批（`approval/request`）：允许一次 / 拒绝。

## 两种作答方式

1. **卡片按钮**（`receive: "callback"`）：飞书卡片带选项按钮和自定义输入框，点按后立即回到 DSH，并自动关闭电脑端的待确认卡片。需要在飞书开放平台为该应用配置「事件与回调 → 长连接 → 卡片回传交互（card.action.trigger）」。
2. **消息作答**（`receive: "poll"`）：卡片列出编号选项，直接在飞书里**回复消息**作答：
   - 单选题回 `1` / `2`；回其他文字即作为自定义答案；
   - 多选题回 `1,3`；
   - 多个问题：每行一条 `1=2`、`2=补充说明`，也可以按顺序逐条回复；
   - 同时有多个请求时，回复开头带请求编号，例如 `p1ab 2`。

## 飞书消息也是双向的

除了卡片按钮，飞书里直接发消息也有回应（`watchMessages` 开启时，默认开启）：

- 有确认请求时：发的文字会被当作答案（编号/自定义文本/`1=2` 批量/`1,3` 多选）；
- 发送「**状态**」：返回桥接是否运行、接收方式、待确认数量、目标应用；
- 发送「**帮助**」：返回用法说明；发送「**ping**」返回 `pong`；
- 私聊里发送其他内容：会收到「已收到，但当前没有待确认请求」的确认回复（群聊为避免刷屏只回应命令与答案）；
- 实现：应用发布 `im.message.receive_v1` 时用长连接实时接收；未发布时退化为对已知会话的轮询（约 30 秒一次）。`watchMessages: false` 可完全关闭消息回复。

`receive: "auto"`（默认）先探测该应用是否发布了卡片回调事件：能收到就用按钮，否则自动降级为消息作答。消息作答在两种模式下都可用。

## 飞书聊天通道（飞书 ⇄ DSH）

设置页的「飞书聊天通道」把飞书里的**普通消息**转交给一个 DSH 会话，并把 agent 的回复同步回这个飞书会话：

- **目标会话**：优先用设置页「绑定会话 ID」；留空时自动选择最近活跃的 DSH 根会话；也可以先让该会话发一张确认卡片，之后同一飞书会话会保持绑定到那个会话；
- **镜像回复**：默认开启，只镜像该会话的 assistant 文本回复（长文本按 ≤3000 字分条发送），不镜像其他会话；
- **群聊**：默认不允许转发（避免群成员驱动 agent），需要时在设置页开启；
- **与确认桥接的关系**：确认请求作答、卡片按钮、「状态 / 帮助」命令优先级更高；只有不匹配任何待确认请求的普通消息才会进入聊天通道，两者互不冲突；
- 关闭「启用聊天通道」或「镜像回复」即可退回纯确认模式。

## 先提交者生效

两条通道同时挂起：电脑端的原生确认面板与飞书卡片。任一通道的提交先到 Host 即生效：

- 飞书先提交：插件返回答案，并中止转发给电脑端的那次请求；电脑端的待确认卡片关闭，不会再次等待。
- 电脑端先提交：飞书卡片被更新为「已在电脑端完成」，之后的飞书提交会收到「已完成 / 已失效」提示，卡片也不会再变回待确认。
- 请求被取消或超时：飞书卡片更新为「已失效 / 已取消」。

## 应用凭据与隔离

插件**不需要改全局 lark-cli 配置**，也不影响其他继续使用 lark-cli 的服务：

- 在插件配置里填 `appId` 和 `appSecret` 后，插件在 `$DSH_HOME/feishu-bridge/lark-cli/` 下维护一个**自己的** lark-cli 配置目录（通过 `LARKSUITE_CLI_CONFIG_DIR` 隔离），凭据只写在这个目录里。
- 不填 `appId` / `appSecret` 时，退回使用宿主 lark-cli 的当前 profile（方便本机快速试用）。
- 其他人安装这个插件后，只需填自己的 `appId` / `appSecret` 和目标任务即可使用。

## 在 DSH 里配置

安装并重启 DSH 后，可以从**左侧栏的「飞书桥接」**或**设置 → 飞书桥接**打开配置页（两处是同一个表单），直接填写并保存：

- **App ID / App Secret**：飞书应用凭据；Secret 只写不读，留空表示不修改。
- **目标群名 / chat_id / 私聊 open_id**：投递位置。推荐用群聊——新建一个群（如「DSH 确认」）把机器人拉进去，填群名即可自动发现。
- **接收方式**：`auto` / `消息作答` / `卡片按钮`。
- **开关**：总开关、问题同步、审批同步。
- **发送测试卡片**：立即验证应用凭据、权限和目标是否可用。
- **热重载插件**：更新插件代码后无需在插件管理里停用/重启（也不需要审批），插件会自行重载；有未完成确认时会拒绝重载以免中断。
- 卡片顶部两行上下文：第一行 **会话标题**（单独一行，便于人识别）；第二行工作目录 · session 短 id（供 agent 精确对应会话）· 时间。
- 状态区会显示当前阻塞原因（凭据无效、机器人未入群、群名不唯一、发卡失败等），据此调整即可。
- **首次安装后需要重启一次 DSH**，浏览器端才会加载这个设置页；之后改配置不需要重启。
- **跨平台**：插件不含硬编码机器路径；`lark-cli` 默认从 `PATH` 查找，找不到时在设置页填完整路径（Windows 可用 `lark-cli.exe`，也兼容 `.cmd`）。配置与日志目录基于 `$DSH_HOME`。
- 所有用户配置（应用凭据、目标、接收方式、开关、lark-cli 路径、并发/轮询等高级项）都在设置页完成，不需要编辑文件。

保存后无需重启：插件会重建私有 lark-cli 环境、重新探测通道并发现目标。配置同时落在 `~/.dsh/feishu-bridge.json`（可直接查看或备份）。字段含义：

```json
{
  "enabled": true,
  "appId": "cli_xxxxxxxxxxxxxxxx",
  "appSecret": "xxxxxxxxxxxxxxxx",
  "receive": "auto",
  "target": { "chatName": "DSH 确认" },
  "allowOperators": [],
  "bridge": { "questions": true, "approvals": true },
  "maxPending": 8
}
```

| 字段 | 说明 |
|---|---|
| `enabled` | 关闭后插件不拦截任何请求。 |
| `appId` / `appSecret` | 专用飞书应用凭据；填写后凭据写入插件私有的 lark-cli 目录，不影响其他服务。留空则使用宿主 lark-cli。 |
| `larkConfigDir` | 自定义私有 lark-cli 配置目录；缺省 `$DSH_HOME/feishu-bridge/lark-cli`。 |
| `target.userId` / `target.chatId` | 机器人私聊的 open_id，或群聊 chat_id；两者填一个。 |
| `target.chatName` | 已配置 `appId`/`appSecret` 时，按群名自动发现目标群（机器人需已在该群）。 |
| `target.discover` | 默认 `true`；只有一个机器人所在群时会自动选它。 |
| `allowOperators` | 允许作答的 open_id 列表；留空时私聊默认只允许 `target.userId`，群聊允许群内任何人。 |
| `bridge.questions` / `bridge.approvals` | 分别开关问题与审批的同步。 |
| `receive` | `auto`（默认）/ `callback` / `poll`。 |
| `pollIntervalMs` | 消息轮询间隔，默认 3000ms；只在有待确认请求时轮询。 |
| `larkCliPath` | lark-cli 可执行文件路径；缺省按 PATH 与 Homebrew 位置查找。 |
| `larkProfile` | 不使用 `appId` 时，传给宿主 lark-cli 的 `--profile`。 |
| `maxPending` | 同时挂起的飞书请求上限，超过时该请求只留在电脑端。 |

配置文件每 5 秒检查一次：修改 `appId` / `appSecret` / 目标 / 开关后**无需重启 DSH**，插件会自动重建 lark-cli 私有环境、重新探测通道并发现目标；改成 `"enabled": false` 会立即让插件停止介入。

## 分享给别人

把插件目录发给对方（或在插件市场/本地目录安装），对方打开同一个「设置 → 飞书桥接」页，填自己的 App ID / App Secret 和目标群即可。插件用独立的 `LARKSUITE_CLI_CONFIG_DIR` 私有目录，不会影响对方已经用于其他服务的 lark-cli 配置。

同一套桥接核心也按「Host 无关」的方式拆分（`lib/card.js` 卡片、`lib/poll.js` 文本解析、`lib/lark.js` 适配），后续要接入 Claude 等其它 Agent 时，复用的是这些模块加一层新的宿主适配，不需要重写业务逻辑。

## 专用应用的最小配置

1. 飞书开放平台新建应用（或使用已有应用），开启**机器人能力**。
2. 权限：`im:message`、`im:message:update`、`im:message:readonly`。
3. 要按钮模式：在「事件与回调」中选择**长连接**接收事件，订阅「卡片回传交互」。
4. 发布版本，把机器人拉进一个群（例如「DSH 确认」）；只填 `appId` / `appSecret` 时插件会按群名或唯一群自动发现目标。
5. 把 `appId` / `appSecret` 填入 `~/.dsh/feishu-bridge.json`，在插件管理里重新启用插件。

## 限制

- 只有解析到可用 `target` 时插件才介入；否则完全等同于未安装。
- 群聊自动发现只覆盖机器人已加入的群；私聊需要显式提供 chat_id / open_id。
- 文本作答每个问题只接受一条答案；先答复的问题会显示「已记录」，全部答完才一次性提交给 DSH。
- 多问题时每个问题的控件紧跟在题干下方，所有问题放在同一个表单里，一次「提交全部答案」完成整批作答。
- 飞书卡片只在发送后 14 天内可更新；更晚的迟到提交只能收到文字提示。
- 子代理会话的请求不桥接（DSH 本身不允许子代理直接向人提问）。
- 该插件不修改 DSH 会话记录，也不替调用方做任何授权决策；它只把人的选择原样送回原有确认通道。
- `testAcceptBotReplies` 是自动化测试开关（默认关闭），开启后机器人自己发出的文本消息会被当作作答，用于无人工参与的端到端验证；日常使用请保持关闭。
